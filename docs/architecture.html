Factory Inventory Management System

Architecture overview: a Vue 3 single-page app over a FastAPI service backed by in-memory JSON data (no database).

System architecture

Three layers, one process per tier. The browser talks to the API directly over HTTP.

Frontend - Vue 3 + Vite, port 3000
main.js router (6 routes) App.vue shell, nav, filter bar views/ Dashboard, Inventory, Orders, Demand, Spending, Reports components/ FilterBar, detail modals, profile, tasks composables/ useFilters, useI18n (en/ja), useAuth api.js axios client
HTTP / JSON  ·  http://localhost:8001/api/*  ·  filters as query params
Backend - FastAPI + Uvicorn, port 8001
main.py routes, Pydantic models apply_filters() warehouse / category / status filter_by_month() month or quarter CORS allow all origins Aggregations dashboard summary, quarterly, monthly trends
import at startup  ·  mock_data.py reads JSON once into module-level lists
Data - JSON files in server/data/, held in memory
inventory.json (32) orders.json (250) demand_forecasts.json (9) backlog_items.json (4) purchase_orders.json (0) transactions.json (56) spending.json (summary, monthly, categories)

Data flow

How a filter change reaches the screen.

Request lifecycle

  1. User changes a filter in FilterBar (period, warehouse, category, order status).
  2. useFilters holds this as a shared singleton (module-level refs). getCurrentFilters() maps the period to a month param.
  3. The view calls api.js, which drops all values and builds the query string.
  4. FastAPI parses the params and filters the in-memory lists with apply_filters and filter_by_month.
  5. Pydantic validates the result against the response_model, and JSON is returned.
  6. The view stores raw data in refs (allOrders, inventoryItems); computed properties derive the totals and charts.

Filter support by endpoint

EndpointFilters
GET /api/inventorywarehouse, category
GET /api/orderswarehouse, category, status, month
GET /api/dashboard/summaryall four
GET /api/demand, /api/backlognone
GET /api/spending/*none
GET /api/reports/*none (computed from all orders)

Inventory has no time dimension, so the month filter does not apply to it.

API surface

Defined in server/main.py. All data is read-only.

Gaps found while reading the code

Things that look unfinished or inconsistent. Worth knowing before you build on them.

TypeObservation
Missingapi.js calls /tasks (GET, POST, PATCH, DELETE) and /purchase-orders (POST, GET), but main.py defines no such routes. Those calls would return 404. The PurchaseOrder models exist but are unused by any route.
Unroutedviews/Backlog.vue exists but is not registered in the router or imported anywhere, so it is unreachable.
ConfigThe API base URL http://localhost:8001/api is hard-coded in api.js, and CORS allows all origins with credentials.
